# Scientific review and repair — 2026-09-07

## Scope and what was actually reviewed

The initial orientation reviewed all **100 tracked `.md`/`.txt`/`.rst` documents**
and LICENSE, including the journal, operational history, engine/port documents,
registry tables, corrections and text evidence. Selected YAML/JSON examples were
also read. This is documentation coverage, not an exhaustive source-code audit.

The starting checkout contained **1,823 tracked files** and **297 Python, shell,
or extensionless `bin/` scripts**. Documentation therefore accounts for about
5.5% of tracked filenames; that percentage is not a meaningful estimate of code
or scientific-evidence coverage. Source inspection was selective and
claim-driven; no line/branch coverage percentage was measured.

| Area | Initial review coverage | Remaining boundary |

## Repairs and evidence boundaries

### Scientific claim propagation

- `emit_clean_scope_report.py` now emits schema `/2`, preserves document-level
  assumptions/provenance and cross-lane qualifications, and keeps historical
  window diagnostics explicitly descriptive. It no longer promotes mixed-lane
  ratios, causal subtraction or the withdrawn 2.52x claim. Both outputs are
  prepared before atomic publication; failure preserves existing outputs.
  Producer-local path strings are rendered as distinct opaque identifiers;
  repository-relative source-analysis paths and file digests preserve the audit
  trail without republishing private filesystem locations.
- `joint_enrich.orderings` requires explicit complete registry context and the
  actual pair predicate. The old generator produced 13 adjacent pairs, 10 of
  which failed that predicate. Current ordering statistics cannot acquire an
  inferential p-value from window count alone.
- `fidelity-stats paired-delta` validates A/B identities and document mappings;
  it uses source-document inference only with complete consistent provenance,
  otherwise reports descriptive-only statistics. It preserves the public B-A
  convention and refuses duplicate/non-finite/incompletely paired data.
- The legacy scalar-floor command no longer treats an `evidence_kind` label plus
  prose as proof of zero. Actual zero-control qualification uses independently
  captured sealed datasets and forced comparison, not a fabricated summary.
  The unused legacy `bf16_floor_summary.py` attribution producer was retired;
  its only executable documentation reference now uses the guarded stats tool,
  and the historical `BF16-FLOOR.json` is preserved unchanged.
- Scientific documents, cards, generated registry commentary and entrypoint
  guidance distinguish reconstruction/serving, finite panels/population inference,
  signed control contrasts/causal attribution, and sampled/full parity.

### Numeric and provenance correctness

- NumPy log-softmax now normalizes shifted logits before adding/subtracting large
  common offsets. Both estimator backends refuse non-finite intermediates even
  when inputs are finite.
- Same-stack classification checks sealed capture source identity as well as
  environment/lane identity. Missing or differing source evidence is advisory,
  not a certified floor.
- Materialized quantized heads retain their actual quantization provenance.
  Own-head comparisons are checked against independent nonzero numeric answers.
- Forced self-comparison now reports `short_circuited: false` when computation
  ran. Its agreement check compares actual float64 bit patterns and top-1,
  refusing nonzero, negative-zero or top-1 disagreement rather than overwriting
  it with the hash proof. Historical sealed receipts are unchanged; earlier
  `short_circuited: true` could coexist with a genuinely executed
  `force_compute_agreed: true` check because the old writer retained the hash
  result's flag.
- Predicate policy `/v2` adds declared producing-evidence checks without changing
  the seven-field comparability key. Replay metadata is copied from exact sealed
  comparison receipts where available; unknown evidence is not inferred from
  names. Different harness hashes are not automatically proof of incompatible
  arithmetic, but they do not certify equivalence either.
  Comparison-to-submission-to-ingestion also retains the available replay
  declaration, so the downstream predicate can veto a conflicting declaration
  rather than losing it at the serialization boundary.
- Honest unknown-direction cross-stack comparisons remain advisory and cannot be
  used as floors. A candidate below an unquantized control is no longer rejected
  by a nonexistent monotonicity theorem; identity and foreign-floor prohibitions
  remain enforced.

### Operational and testing correctness

- Remote downloads require an explicit protected download credential; a publisher's
  token is not a fallback. Reused publication-token bytes, including copied files,
  refuse before provider access or transport. Distinct bytes do not certify HF
  permission scope: the operator must select a read-only download token.
- Publication job identity retains authorization facts but excludes observation
  time and its derived seal. The full sealed observation remains bound in the
  execution attempt. Historical job identities remain verifiable unchanged.
- Requested native parity fails construction/forward errors and missing coverage.
  Reference-only execution remains explicitly unqualified. mHC load comparison
  uses independently read checkpoint values.
- Source-string and mock-echo assertions were replaced in the touched battery,
  credential and numeric paths. The safety test now executes the real planning
  boundary and verifies that a credential changed after planning never reaches
  execution; it does not count calls in source text as proof.
- The shared skip classifier exposes nested skipped checks while rejecting empty
  JSON skip lists and passing labels that merely discuss skipping. Counts are
  **notices**, potentially including summaries, not independent test counts.
- Changelog generation excludes commits that modify only the generated
  `CHANGELOG.md`, not commits merely named `changelog:`. A real scratch-Git
  scenario proves self-commit stability and continued detection of code changes.
- The supposedly enabled `reportPossiblyUnbound` setting was invalid. A canary
  established the actual switches required by Pyright 1.1.413. Enabling the broad
  rule produced 114 reports over 237 files: control-flow inspection explained
  111 as valid correlated guards; two import-error masking sites were repaired,
  and a pipeline selftest import was moved outside its expected-error check.
  The broad rule remains explicitly off because it fails the repository's
  wrong-code-only policy. Definite-unbound/undefined and annotation checks remain;
  no placeholder initializers or per-line suppressions were added.

## What to improve next, in priority order

1. **Build an independently sourced, calibration-audited panel.** Preserve old
   panels as separate identities. Record document/source clusters and strata,
   predeclare selection/weighting, and scan the actual selected spans against
   available quantizer calibration. One corpus5x5 source is byte-identical to a
   document the larger suite excluded for overlap; that alone does not prove
   overlap in the selected token slice or every candidate's calibration. A new
   panel requires new captures, not relabeling old numbers.
2. **Complete producing-evidence coverage and independent reproduction.** Publish
   usable reference/candidate captures, exact source closures, replay/BLAS/device
   facts and independent reproduction records. Resolve metadata warnings by
   evidence, not reconstructed guesses. Add explicit measured equivalence bridges
   where harmless code changes make hashes differ; do not make differing hashes
   silently equivalent.
3. **Qualify native reconstruction and full forward behavior separately.** Test
   complete EXL3 reconstruction including rounding, relevant activation-quantized
   kernels, and full-model/cache behavior on actual supported hardware. Sampled
   pre-Hadamard equality does not retire `weights_reconstructed`. The draft port
   remains unqualified until its requested real native comparisons run.
4. **Extend the estimand deliberately.** Add independent long-context, prefill/decode,
   sparse-attention and task-quality experiments under separate protocols. Do not
   infer generation quality from the current teacher-forced 2,048-token panels.
5. **Benchmark complete nonzero candidate workflows.** Include fetch, setup,
   materialization, cold captures, comparison, retrieval and failure/teardown
   reserves. Repeat timings and compare identical numerical policies/content.
   The historical 10.13x replay result is a root self-comparison; it is not a
   universal candidate speedup. The incorrect 76,800 expert-matrix multiplier and
   whole-family budgets omitting candidate captures were withdrawn, not replaced
   with invented timings.
6. **Continue the test-quality audit by executable boundary.** Inspect remaining
   historical source-text/declared-coverage tests, optional oracle tiers and
   architecture-specific skips. Prefer explicit required coverage and wrong-input
   controls. A test manifest's assertion count is a declaration, not runtime
   branch coverage. Preserve before-fix failure evidence for new regressions.
7. **Audit publication and external state separately.** Reconcile deployed HF
   cards/mirrors with these corrected local producers only with approval for
   those destinations. Inventory retained versus digest-only/lost captures,
   artifact identities, missing top-1/control evidence and unresolved warnings.
8. **Review the newly arrived Explorer end to end.** Audit its dependency/runtime
   exposure, bounded worker/parser behavior, URL and filesystem boundaries,
   concurrency/resource limits, accessibility and deployment synchronization.
   The local integration/browser smoke is not a penetration or load test.

These are evidence gaps or new experiments, not permission to weaken existing
refusals. Paid/GPU experiments and external publication require separate explicit
authorization and a realistic end-to-end budget.

## Native qualification and test-audit continuation

This continuation does not qualify native reconstruction or serving, does not
change the production EXL3 decoder arithmetic, and does not replace the frozen
native receipt or published registry values. QFS Explorer is outside its scope.

The native EXL3 producer now emits separate v2 observations at explicit new
destinations. A pinned wheel is byte-verified before installation, installed
implementation bytes are checked afterwards, and an unchanged version string
cannot stand in for that evidence. Exact required module/case coverage and
finite, nonempty, same-shape/same-dtype byte comparisons gate each stage.
Native module forward invokes `LinearEXL3.forward`; its branch labels derive
from pinned predicates, not kernel instrumentation. Whole-model/cache/serving
qualification remains false regardless of the module result. New observations
retain native weight bytes for isolated windows and full-matrix slices so a
later mismatch can be diagnosed offline instead of retaining only hashes.

Existing observations cannot be overwritten, and failed JSON serialization
cannot leave a partial observation. A server that ignores an exact byte-range
request is refused before its body is read; tensor geometry and fetch sizes are
bounded. The comparator now accepts the frozen native evidence only when both
its reviewed digest and the current decoder bytes match. Forged aggregates,
empty/partial coverage and changed decoder code cannot inherit its claim.

Layer evidence names required, observed, passed and missing cases. Duplicate or
unrelated rows cannot satisfy the requirement; invalid geometry, non-finite
metrics and bad tolerances refuse. mHC-only selection does not require unrelated
attention/MLP architectures. Truncated experts and untested sparse/cache regimes
remain explicit. Synthetic reference tests exercise independent loading,
causal/carried-state behavior, sparse selection and mHC invariants, not native
implementation parity.

The test audit also removed source/signature assertions that did not execute a
device path. Missing live native oracles are visible skips, while an available
oracle's execution error is a failure. The bundle now includes its required
frozen native fixture in both the bundle and Docker build context. Its runner
no longer excuses an assertion failure merely
because earlier output mentioned `quant_pipeline`, and surfaces nested skips.

Scratch reversions restored seven defects and failed their focused checks:
dtype narrowing hiding a difference; unbounded response reads; an earlier
pipeline notice masking a later assertion; flattening invalid tensor geometry;
accepting stale/forged native evidence; leaving partial JSON on serialization
failure; and dropping native `[SKIP]`/`skip(s)` notices from the outer battery.
Positive controls passed with the fixes present. Real CPU-host CLI
execution also refused a required native observation before fetching or writing
anything, and `--require-live-native` failed rather than silently skipping.
